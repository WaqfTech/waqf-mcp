# Security Policy

| Version | Supported          |
| ------- | ------------------ |
| 1.x     | :white_check_mark: |

## Reporting a Vulnerability

We take the security and integrity of Islamic digital infrastructure with utmost seriousness and religious responsibility. If you discover a security vulnerability, flaw, or data leakage vector in `waqf-mcp`, please follow responsible disclosure practices.

### How to Report Privately

- **Preferred**: Use **[GitHub Private Vulnerability Reporting](https://github.com/waqftech/waqf-mcp/security/advisories/new)** to submit your report confidentially.
- **Email**: Alternatively, report directly to **`security@waqftech.org`** with details, reproducing steps, and expected impact.

> [!CAUTION]
> **Please do not report security vulnerabilities through public GitHub issues, discussions, or social media.**

### What to Include in Your Report

1. Description of the vulnerability and its potential impact.
2. Step-by-step instructions or minimal Proof of Concept (PoC) to reproduce the issue.
3. Relevant request logs, headers, or affected endpoints.
4. Any potential remediations or patches you have identified.

### Response & Disclosure Process

1. **Acknowledgement**: We acknowledge receipt of vulnerability reports within **48 hours**.
2. **Assessment & Triage**: Our engineering team investigates and assesses the issue within **5 business days**.
3. **Remediation**: We prepare and test edge patches in our private staging environment.
4. **Coordinated Disclosure**: Once patched and deployed across Cloudflare edge workers, we publish a Security Advisory crediting the finder.
